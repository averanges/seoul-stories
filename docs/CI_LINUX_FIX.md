# npm test: Windows / Linux checkout

## Причина

Первый GitHub checkout хранит исходники с LF, а часть локальных файлов Windows имела CRLF или смешанные окончания строк. Сохранённые SHA-256 в 11 манифестах учитывали исходные байты Windows. Git нормализовал текст при первом add/checkout, и десять тестов сохранности стали видеть другой хеш при неизменном коде. `git ls-files --eol` подтвердил `i/lf` и `w/mixed` для main.tsx/cinematic.css. Сценарий, медиа, маршруты и Web Audio не были причиной сбоя; предупреждение MockTimers Node 22 не являлось ошибкой.

В отдельной LF-копии воспроизведён тот же итог: **71 тест, 61 pass, 10 fail**, как на скриншоте Actions. На Node 22.23.4 воспроизводятся те же десять проверок контрольных сумм.

## Исправление без отключения проверок

- `src/integrity.ts`: SHA-256 текста вычисляется после единственного преобразования CRLF → LF. Пробелы, BOM, отдельный CR и все остальные байты остаются значимыми. Нормализация работает по байтам и не скрывает повреждения UTF-8.
- PNG/JPG/WebP/WAV/MP3 и другие бинарные файлы проверяются строго по исходным байтам.
- Все прежние проверки сохранены. Их вычисление хеша переведено на общий helper; сравнения сценариев, схемы, развилок и аудиофрагментов продолжают выполняться.
- 28 текстовых эталонов переведены в LF-форму. Миграция выполнена только когда прежний SHA совпал с текущими неизменёнными байтами исходника. Несовпадающие исторические значения и бинарные хеши не переписаны. Старые и новые значения перечислены в `CI_HASH_MIGRATION.json`.
- `.gitattributes` фиксирует LF для текста и явно запрещает обработку бинарных медиа как текста.
- Четыре новых теста проверяют эквивалентность LF/CRLF/смешанных строк, обнаружение реального изменения текста/пробелов/BOM, строгую проверку бинарных файлов и различимость некорректных UTF-8 байтов.

## Воспроизведение и итог

| Среда проверки | До | После |
|---|---:|---:|
| Node 24.22.0, рабочая Windows-копия | 71/71 | 75/75 |
| Node 24.22.0, LF-копия | 61/71 | — |
| Node 22.23.4, LF-копия до исправления | 61/71 | — |
| Node 22.23.4, текущая Windows-копия | — | 75/75 |
| Node 22.23.4, отдельный Git checkout с LF | — | 75/75 |
| Node 22.23.4, отдельная копия с CRLF | — | 75/75 |

В последней проверке использован временный альтернативный Git index: выгружены HEAD и текущие исправления, без изменения рабочего index. LF/CRLF-копии проверены с теми же аргументами, что выполняет npm test. Пропусков, отменённых тестов и замен проверок заглушками нет. Валидация всех историй и production-сборка также проходят.

Это локальное воспроизведение Git checkout и Node 22 **на Windows**, не запуск настоящего Ubuntu: установленной Linux-среды здесь нет. Окончательное подтверждение самого Ubuntu runner даст следующий GitHub Actions после push. Ошибка окончания строк воспроизведена независимо от ОС с точно тем же результатом 61/10.

## Новый push

Нужно включить в один коммит `.gitattributes`, `src/integrity.ts`, `src/integrity.test.ts`, изменения существующих `src/*.test.ts`, `package.json` и изменения манифестов/этот отчёт в docs. Перед коммитом: `npm test`, `npm run validate`, `npm run build`. Сценарные JSON в public, изображения и аудио не изменялись.

Рабочие изменения подготовлены; коммит, push и публикация этим исправлением не выполнялись. Workflow не ослаблялся и по-прежнему запускает полный npm test.
