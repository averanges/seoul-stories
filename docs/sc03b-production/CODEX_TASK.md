# Короткое ТЗ Codex — SC03B «Охранник»

**Задача:** добавить SC03B как общую сцену для двух входов в текущий проект Seoul Stories, не создавая новый плеер и не меняя утверждённые сцены 1/2/3A.

1. **Изучить реальные ID и schema проекта** (`nodes.json`, `scenes.json`, `story.json`, engine). `data/SC03B_content.json` — переносимый контракт, не готовый drop-in под любую schema. Использовать канонические тексты, перевод, учебные заметки, порядок и граф из него.
2. **Маршруты:** после прямого выбора охранника в SC02 (`route=investigate`, `SC02_R_CHECK`) открыть общую SC03B с D04 variant=`direct`; после SC03A выбора `check` (`guard_visit_context=after_shelf`, `SC03A_R_CHECK`) открыть ту же сцену с D04 variant=`after_shelf`. Не переписывать остальную сцену, не путать четверг (визит) и пятницу (звонок).
3. **Пять НОВЫХ полноформатных 16:9 игровых изображений** `SC03B_SH01`…`SC03B_SH05` с сохранением лица Юны из `references/SC01_Yuna_final_reference.jpg` и одежды из `references/SC02_Yuna_outfit_reference.jpg`. Приоритет у лица из реальных игровых кадров, **НЕ из последующих неудачных раскадровок**. Файл `references/SC03B_first_storyboard_reference.png` — референс атмосферы, **не резать на панельки**. Если генерация недоступна, не выдавать чужие/раскроенные изображения за полноценные assets: предоставить prompts и blocker.
4. **Режиссура и монтаж:** SH01 подход → SH02 спокойный боковой two-shot → SH03 фронтальный план спокойного охранника → SH04 фронтальный крупный план Юны (сильный шок) → SH05 широкий план одинокой Юны. Не повторять почти одинаковый крупный план Юны на кадрах 2–4. **D09 (поцелуй) показывается ещё на SH03, а при переходе на D10 происходит резкий cut в SH04**. В D10 желательно короткое удержание без текста перед появлением фразы (если плеер это поддерживает без отдельного кадра).
5. Одна иллюстрация поддерживает несколько **последовательных** реплик. После продвижения к следующему кадру старый кадр не возвращается. Без встроенных титров, облачков или интерфейса в арте; тексты — только в плеере. Не показывать Сору, поцелуй или запись камер.
6. **Кнопка «Проще»:** original/simple на каждом узле; меняет только текущую реплику, не кадр/состояние; на следующей автоматически оригинал. Если версии идентичны, скрывать кнопку. Учительский режим показывает обе версии, перевод, грамматику, словарь, комментарий.
7. **Факты сюжета:** D05 устанавливает `guard_reports_other_woman=true`, D09 — `guard_reports_kiss=true` и `yuna_heard_kiss_report=true`. Сохранить route/first_question/факт посещения полки и всю историю выбора. НЕ устанавливать `sora_involved`, `sora_identity_known` и `minsu_confessed`. Не превращать сообщение охранника в показанный флешбек.
8. **Выход:** после D16 автоматически перейти на `SC04A_START` при прямом маршруте или `SC04B_START` после полки. Это символические метки; найти реальные ID или оставить рабочие заглушки до разработки 4A/4B. Нельзя направлять на несуществующий узел.
9. **Тесты:** 16 текстовых шагов и 5 изображений на обоих входах; D04 различается правильно; D09→D10 даёт эмоциональный перелом; переход/Back/Restart/Autosave/Teacher Mode/Simple не ломаются; последняя версия сцены не меняет данные SC01/SC02/SC03A; картинки настоящие standalone images (не crop).

**Архив:** `README.md`, `SC03B_FULL_SHOT_CARDS.md`, `SC03B_DIALOGUE_READING.md`, `data/SC03B_content.json`, `references/` и `assets/`. После сборки перечислить фактические ID переходов, разрешение и число игровых изображений, а также явные ограничения.
