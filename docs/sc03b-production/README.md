# Seoul Stories — SC03B «Охранник» / 경비실

**Готовый пакет для Codex**, продолжающий SC02 и, по другой ветке, SC03A. Это материалы сценария, генерации 5 игровых изображений и интеграции в **существующий** кинематографичный плеер; не новый движок.

## Содержимое

- `data/SC03B_content.json` — единственный канонический источник идентификаторов, текста и веток.
- `SC03B_FULL_SHOT_CARDS.md` — пять режиссёрских карточек, критерии генерации и реплики.
- `SC03B_DIALOGUE_READING.md` — текст сцены подряд для проверки двух языковых вариантов.
- `CODEX_TASK.md` — краткая постановка задачи и проверочные критерии.
- `references/` — лицо Юны по финальным игровым кадрам, её актуальная одежда из SC02, исходная первая раскадровка SC03B (НЕ для нарезки) и паспорта внешности.
- `assets/scene_03b/_PLACE_FINAL_IMAGES_HERE.txt` — только место для новых игровых изображений; **они ещё не сгенерированы**.

## Решения, которые нельзя менять без согласования

1. Пятница — звонок охранника; четверг — посещение Минсу и наблюдение; суббота — разговор.
2. Два входа: непосредственно из SC02 и после сцены с полкой SC03A. Меняется только вопрос Юны D04, визуальный ряд общий.
3. Лицо Юны совпадает с утверждёнными игровыми SC01/SC02. Одежда такая же, как в конце SC02, даже если на первой предварительной раскадровке иная.
4. Ключевое известие о поцелуе сказано охранником на SH03; **SH04 начинается с шокированной реакции** Юны, без охранника в кадре.
5. Никогда не показывать поцелуй или Сору. Охранник видел женщину, но не узнает её, потому что не знаком с ней.
6. Нет выбора внутри SC03B: выход на SC04A (если сразу к охраннику) или SC04B (если до того Юна видела полку).

## Техническая оговорка

Все ссылки `SC03B_START`, `SC04A_START`, `SC04B_START` — **символические названия переходов**, а не утверждение о существующих ID. Codex должен найти фактические ID и подключить только рабочие цели. Если 4A/4B ещё нет, оставить рабочую заглушку маршрута.
