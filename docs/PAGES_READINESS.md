# Проверка мобильной версии и GitHub Pages

Проверено 9 ноября 2026. Публикация не выполнялась, удалённый репозиторий не создавался и не изменялся.

## Что было до проверки

Проект — полностью статический React 19 / TypeScript / Vite, JSON-истории и локальные изображения/аудио. Серверной логики, секретного музыкального API и обязательного backend нет.

Мобильная адаптация уже существовала: breakpoint 760 px, отдельные размеры текста, вертикальные варианты выбора, масштабирование кадров, пульт учителя с прокруткой. Были также стили планшета/невысокого десктопа. Исходный замер: горизонтальной прокрутки не было, но основные кнопки имели размер меньше 44 px. Короткая горизонтальная ориентация не имела отдельной компоновки, отсутствовали safe-area отступы; мобильная кнопка преподавателя теряла понятное доступное имя.

## Исправления

- Добавлены touch-зоны не меньше 44×44 px для основных действий и управления звуком.
- Safe-area insets и `viewport-fit=cover` для вырезов/нижнего индикатора.
- На смартфонах/планшете в портрете изображение занимает верхнюю часть экрана с сохранением лиц; текст и варианты ниже. Исходные иллюстрации не перерабатывались.
- На коротком горизонтальном экране реплика и выборы расположены рядом. Длинный текст может прокручиваться внутри блока, управление «Дальше»/«Проще» остаётся доступным.
- У пульта учителя закреплена кнопка закрытия; исправлена ширина звукового меню. Пульт и настройки не создают горизонтальной прокрутки.
- Убран обязательный запрос всех иллюстраций при открытии истории. Текущий кадр загружается по необходимости; полный набор проверяется перед публикацией и автоматическим тестом.
- Пути музыки учитывают Vite base, как уже учитывали пути истории/картинок. Проверена именно подпапка `/seoul-stories-test/`, а не только корень localhost.
- При скрытии страницы AudioContext приостанавливается, при возвращении возобновляется тот же контекст. Если настоящий мобильный браузер потребует повторный жест, используется кнопка музыки. Проверка событий не заменяет аппаратное сворачивание Safari/Chrome.
- Полные треки представлены в production как MP3 160 kbps: суммарно около 5,1 MiB вместо 45,5 MiB WAV. Оригиналы WAV сохранены в исходном проекте; адаптивные intro/loop/outro не перекодированы, их длительности и сюжетные события сохранены.
- Из production исключены 25 неиспользуемых старых JPG и четыре заменённых полных WAV. Сценарные JSON, иллюстрации и ветвления не изменены.
- Тест финала A теперь использует сохранённые SHA-256 утверждённых оригиналов, а не соседнюю папку вне репозитория. Это позволяет воспроизводить тесты в чистом GitHub Actions checkout.

## Проверки

Размеры: 360×800, 390×844, 430×932, 768×1024, 1920×1080 и обратные ориентации 800×360, 844×390, 932×430, 1024×768, 1080×1920. Проверяются длинная корейская реплика, три выбора, финал/изображение и учительский пульт, прокрутка, доступность кнопок и звуковых настроек. Скриншоты находятся в Playwright `test-results`; HTML-отчёт — `playwright-report/index.html`.

Проверяется достижимость всех маршрутов движком и пять репрезентативных прохождений через интерфейс: A, B через личный/телефонный разговор, C через личный/телефонный разговор. Пройдены оба временных титра, все иллюстрации отвечают по HTTP, Original/Simple, возврат и обновление страницы на концовке.

Фактический результат: **71/71** тест движка/данных и **25** успешных проверок Playwright (13 Chromium, 12 WebKit), **1** явный пропуск аудио Windows WebKit. Оба браузера прошли все десять размеров и ориентаций, пять прохождений A/B/C и проверку ресурсов/обновления страницы. Ошибок выполнения игры и ответов 404 её ресурсов в успешных прогонах не было.

Аудио проверяется в мобильной эмуляции с touch: запрет старта до жеста, декодирование MP3/WAV из подпапки, громкость, выключение, пауза/возобновление при visibilitychange, отсутствие второго AudioContext, смена сцены, повтор C и выход в библиотеку. До этого отдельно выполнены трёхминутные реальные прогоны спокойной петли SC06/B и пятиминутные моделируемые тесты. Музыкальная естественность новых петель всё ещё требует человеческого прослушивания.

Chromium с Chrome и WebKit запускаются через Playwright. Windows WebKit 27.2 в этой среде не предоставляет AudioContext: его аудиотест явно пропускается, а не засчитывается как успешный. Интерфейс и маршруты WebKit проверяются отдельно; аудио проходит в Chromium. Это приближает проверку Android Chrome/iOS Safari, но не является проверкой на настоящих устройствах. Перед публичным выпуском нужны реальные iPhone и Android: вырезы экрана, адресная панель, системный mute/громкость, блокировка экрана, сворачивание/возвращение, длительное чтение и Bluetooth/наушники. Полноэкранный API зависит от устройства; если он недоступен, текущий плеер показывает уведомление и продолжает работать.

## Размер и содержимое

Сборка около 51,8 MiB, из них аудио 25,8 MiB. Максимальный отдельный файл около 4,7 MiB. Это размер всей библиотеки, не загрузка при каждом открытии: ресурсы выдаются по необходимости. Предзагрузка будущих адаптивных треков ограничена intro/loop; эмоциональная часть предварительно подгружается ближе к её событию (SC06_D21–D25 и ENDING_C_D03–D05), без запуска. Неиспользуемые исходники, docs, node_modules, временные скриншоты и секреты не попадают в dist. `PRODUCTION_SIZE_REPORT.json` содержит фактическую ведомость.

Проверены точный регистр путей для Linux, существование ресурсов и характерные форматы секретных ключей в JS/JSON/HTML/CSS/SVG. Найденных ключей нет. Шрифты Google Fonts по-прежнему внешние с системным fallback; это не серверная зависимость игры.

## Локальный запуск проверенной production-версии

Из корня **этого проекта** (`outputs/novel-engine`):

```sh
npm ci
npm run validate
npm test
npm run build:pages-test
node scripts/serve-pages.mjs
```

Открыть http://127.0.0.1:4174/seoul-stories-test/?story=neoreul_mideo . Сервер строго обслуживает подпапку и возвращает 404 для неправильных корневых URL, чтобы ловить ошибки, скрываемые dev-сервером Vite.

Для браузерных тестов:

```sh
npx playwright install chromium webkit
npm run test:e2e
```

В Windows можно указать существующий Chrome через `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH`; WebKit устанавливается Playwright отдельно. На Linux CI используются браузеры Playwright.

Обычная сборка `npm run build` использует относительный base `./`. Для адреса конкретного репозитория переменная `PAGES_BASE` задаёт `/ИМЯ-РЕПОЗИТОРИЯ/`; в workflow значение автоматически получает action configure-pages, поэтому имя не зашито вручную. Приложение использует query `?story=...`, а не серверные маршруты: обновление страницы работает на обычной статике.

## Что остаётся для публикации

1. Проверить на настоящих iPhone/Android перечисленные аппаратные сценарии.
2. Выбрать GitHub-репозиторий и поместить **содержимое папки novel-engine** в его корень: package.json, src, public, docs, scripts, tests, .github. Родительские work/attachments/generated_images не нужны.
3. В Settings → Pages выбрать GitHub Actions. При желании настроить требование ручного подтверждения environment `github-pages`.
4. Обычный push/PR запускает только проверки. Workflow `.github/workflows/pages.yml` намеренно не публикует автоматически. Когда версия будет одобрена, вручную выполнить workflow_dispatch с `publish: true`: проверка → сборка с реальным base → Pages artifact → deploy.

Сейчас ничего из этих внешних действий не выполнено. Конфигурация подготовлена по официальным руководствам [Vite](https://vite.dev/guide/static-deploy) и [GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages).
