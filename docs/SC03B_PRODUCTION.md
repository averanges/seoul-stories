# SC03B «Охранник» — интеграция Production Pack

**Обновлённое демо в текущем сеансе:** http://localhost:5180/?story=neoreul_mideo

На порту 5173 обнаружена отдельно запущенная предыдущая копия проекта, поэтому новая версия запущена на 5180. Она не изменяет её данные localStorage: браузер разделяет сохранения по порту. Сам формат сохранений обратно совместим; при обновлении сайта по прежнему адресу старый прогресс восстанавливается.

Чтобы запустить эту копию самостоятельно:

```sh
npm install
npm run dev -- --host 127.0.0.1 --port 5180 --strictPort
```

## Два входа

- **Прямой:** выбор охранника в SC02 → `SC02_R_CHECK` → «Дальше» → `SC03B_D01`. `route="investigate"`, полку Юна не видела.
- **После полки:** выбор проверки в SC03A → `SC03A_R_CHECK` → «Дальше» → та же `SC03B_D01`. Сохраняются `route="talk"`, `guard_visit_context="after_shelf"`, `shelf_seen=true`.

Для быстрой проверки используйте пульт преподавателя: сначала `SC02_D26` и нужный выбор. После разговора с Минсу можно перейти к `SC03A_D15` и выбрать охранника. Произвольный прыжок в SC03B без подходящих флагов возвращает к выбору SC02.

## Текст, изображения и монтаж

Все 16 текстовых шагов и original/simple импортированы из `SC03B_content.json`. Внутри сцены нет выбора. Меняется только D04: после полки Юна спрашивает, был ли Минсу один. Его original, simple, русский перевод и уточняющий комментарий выбираются совместно; кнопка «Проще» не возвращает прямой вариант вопроса.

Пять **новых отдельно сгенерированных** кадров:

| Файл в `public/stories/neoreul_mideo/assets/scene_03b/` | Использование |
|---|---|
| `SC03B_SH01.webp` | D01: подход к посту охраны |
| `SC03B_SH02.webp` | D02–D04: спокойный боковой общий разговор |
| `SC03B_SH03.webp` | D05–D09: фронтальный план охранника, включая сообщение о поцелуе |
| `SC03B_SH04.webp` | D10–D14: фронтальная шокированная реакция Юны, охранник за кадром |
| `SC03B_SH05.webp` | D15–D16: широкий план одинокой Юны после разговора |

Фотографии поцелуя, другая женщина, Сора и раскрывающие записи камер не показаны. Исходная раскадровка использовалась только как ориентир постановки. Лицо Юны привязано к финальному SC01, одежда — к SC02. Охранник сохраняет лицо, тёмную форму и кепку.

После D09 выполняется резкая смена на SH04. В D10 изображение показано сначала без текста, затем через 650 мс появляется короткая реплика. На время этой паузы продолжение заблокировано, чтобы не проскочить момент. Смена говорящего в D12/D14 не возвращает кадр охранника. D12 original и simple совпадают, поэтому кнопки «Проще» нет.

**Ограничение графики:** все пять файлов имеют нативное разрешение **1672×941**, без программного увеличения. Игровые WebP quality95 сохраняют эти размеры; PNG-оригиналы приложены отдельно. Один первоначальный результат SH03 был отклонён из-за встроенных подписей; после отдельной правки подписи удалены, проверенный чистый кадр включён в проект. Запросы сохранены в `sc03b-production/GENERATION_PROMPTS.md`.

## Флаги и возврат

На входе в D05 применяется `guard_reports_other_woman=true`. На входе в D09 — `guard_reports_kiss=true`, `yuna_heard_kiss_report=true`. Это флаги сообщения охранника, а не новый флешбек или установление личности женщины. `sora_involved`, `sora_identity_known`, `minsu_confessed`, `shelf_disproved` не добавлены.

Эффекты узла входят в его снимок состояния. Возврат с D09 на D08 отменяет флаги поцелуя; с D05 на D04 — флаг женщины. Повторная загрузка не применяет эффекты заново. `first_question`, `route` и все флаги полки сохраняются. Перезапуск сбрасывает новые флаги в false.

## Выходы

На D16 нажмите «Дальше»: маршрут выбирается автоматически, без дополнительного выбора.

- Прямой вход → `SC03B_TO_SC04A` → «Продолжение следует», SC04A.
- После полки → `SC03B_TO_SC04B` → «Продолжение следует», SC04B.

Это действующие временные экраны на SH05, без новых сюжетных реплик и иллюстраций. Сцены SC04A/SC04B не созданы, ссылок на отсутствующие `SC04A_START`/`SC04B_START` нет. На каждом входе — 16 текстовых шагов, затем соответствующий служебный экран продолжения.

## Что изменено

- В прежнем контенте изменены только исходящие связи `SC02_R_CHECK` и `SC03A_R_CHECK`: вместо заглушки они ведут в SC03B. Все утверждённые реплики и изображения SC01/SC02/SC03A сохранены.
- В данные добавлены 16 узлов, два временных экрана, пять сцен/медиа, персонаж охранника и метка внутренней речи Юны; три новых флага включены в существующую миграцию сохранений.
- Движок получил необязательные `onEnterEffects` и расширенный вариант реплики с original/simple/переводом. Для старых историй поведение прежнее.
- UI использует выбранную языковую запись в обычном и учительском режиме. Для D10 добавлена необязательная задержка текста; `SceneImage` поддерживает `transition="cut"`. Компоновка, стили и навигация не заменены. Пустой текст служебной заглушки не создаёт пустую диалоговую панель.
- Обновлены типы, схема JSON, валидатор и тесты. Новые проверки: `src/sc03b.test.ts`.

## Проверки и исходные оговорки

32 автоматические проверки охватывают обе версии D04, два входа/выхода, 16 шагов и пять кадров, флаги/отмену/refresh, старые сохранения и неизменность утверждённого контента. Также выполняются валидатор, production-сборка и браузерная проверка двух полных маршрутов, teacher mode, original/simple, паузы D10, back/restart/fullscreen и размеров 1440×900, 1280×720, 390×844.

Каноническая формулировка D02 оставлена буквально, включая `어제`: в пакете её перевод и учительская заметка относят «вчера» к пятничному звонку. Посещение и наблюдение в остальных репликах явно относятся к четвергу. Языковую редактуру без согласования не выполняли.

В паспортах персонажей есть относительные ссылки на портреты, отсутствующие в исходном ZIP. Для генерации использованы реально приложенные финальные изображения SC01/SC02 и доступный нейтральный портрет. Недостающие ссылки паспорта не используются игрой.
