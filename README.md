## Запуск

Требуется Node.js 22 LTS и npm. Откройте терминал в папке проекта:

```sh
npm install
npm run dev
```

Откройте адрес, который напечатает Vite (обычно http://localhost:5173). Двойной щелчок по `index.html` не заменяет сервер: браузер должен загружать JSON через HTTP.

```sh
npm run validate   # проверка историй, ссылок и файлов иллюстраций
npm test           # маршруты, переменные, возврат, условия, сохранения
npm run build      # TypeScript + production-сборка в dist/
npm run preview    # просмотр production-сборки
```

## Как играть

1. Откройте историю из библиотеки. Сохранённая сессия этого браузера восстановится автоматически.
2. Читайте реплику. На экране выбора ученик сначала отвечает вслух и затем нажимает действие.
3. Реакция персонажа заменит исходный текст, варианты исчезнут. «Дальше» продолжает историю.
4. «Назад» из реакции отменяет выбор и все его эффекты; со следующего экрана возвращает к реакции. Повторное нажатие отменяет выбор.
5. «Начать заново» сбрасывает текущую историю. «Очистить прогресс» удаляет её сохранение и возвращает в библиотеку. Другие истории не затрагиваются.

Клавиши: `→`, `Пробел`, `Enter` — дальше; `←` — назад; `1`–`4` — выбор. Когда фокус на кнопке или селекторе, работают обычные клавиши браузера. Полноэкранный режим — кнопка ⛶ (зависит от поддержки браузером).

Режим преподавателя показывает примеры ответов, ID экрана, текущие переменные, журнал выборов и переход к экрану. Переход сохраняет переменные и добавляется в историю возвратов. Это инструмент тестирования, а не автоматическое прохождение пропущенных сцен. Для проверки маршрута с начальными значениями начните заново.

## Добавить историю без изменения кода

1. Скопируйте папку `public/stories/template` в `public/stories/my-story`.
2. В `story.json` измените `id` на `my-story`, заголовок, описание, уровень, длительность и стартовый экран. Пути `characters`, `scenes`, `nodes` указывают на JSON-файлы в этой папке. Можно также хранить эти поля непосредственно объектами/массивом в `story.json`.
3. Замените `cover.svg`, добавьте свои изображения (SVG, WebP, JPG, PNG) и укажите их относительные пути в сценах. Персонажи описываются в `characters.json`.
4. Напишите экраны и переходы в `nodes.json`. У каждого экрана уникальный `id`; ссылки `next`, `target`, `fallback` ведут на эти ID.
5. Добавьте запись в `public/stories/catalog.json`:

```json
{
  "id": "my-story",
  "title": "Новая история",
  "subtitle": "새로운 이야기",
  "description": "Краткое описание на русском.",
  "level": "A2 · 초급",
  "duration": "15 минут",
  "cover": "my-story/cover.svg",
  "path": "my-story/"
}
```

6. Выполните `npm run validate`, затем `npm run build`.

В `story.json` можно добавить `"$schema": "../story.schema.json"` для подсказок редактора. Схема поддерживает ссылки на отдельные файлы; команда validate дополнительно проверяет их объединённое содержимое, граф и наличие изображений.

## Формат данных

### Персонажи

```json
{"guide":{"name":"Юна · 유나","role":"Студентка","color":"#e9b680"}}
```

### Сцены и расположение текста

```json
{
  "platform": {
    "src": "images/platform.webp",
    "label": "Вечер на станции",
    "characters": [{"id":"guide","x":0.77,"y":0.55}],
    "faces": [{"x":0.72,"y":0.2,"width":0.12,"height":0.22}],
    "safeArea": "left",
    "focus": {"x":0.72,"y":0.45}
  }
}
```

Координаты нормализованы от 0 до 1 от левого верхнего угла полного изображения. Указывайте область лица с небольшим запасом. `characters` хранит позиции персонажей для будущих редакторов; компоновка использует `faces`.

`position` экрана: `auto` (по умолчанию), `left`, `right`, `bottom`, `center`, `narrator`. Автоматический режим пробует `safeArea`, затем свободные области слева, справа, по центру и снизу, проверяя пересечение с `faces`. Ручное положение при пересечении лица также заменяется нижней панелью. `narrator` — нижняя панель без имени.

На широком экране кадр сохраняет 16:9. Панель ограничена рассчитанной областью, длинный текст прокручивается внутри. Нижняя панель — резерв при отсутствии безопасной области. Если и она пересекает лицо, движок размещает её под иллюстрацией, сохраняя весь кадр. На экранах до 700 px иллюстрация остаётся 16:9, а диалог располагается под ней: лица не перекрываются, текст не уменьшается до нечитаемого размера. `focus` передаётся в CSS `object-position`, пригодится также для будущих режимов кадрирования. Текущая версия сохраняет весь кадр на телефоне.

Иллюстрации предварительно загружаются и проверяются при открытии истории. Если несколько экранов ссылаются на одну сцену, элемент изображения сохраняется; текст анимируется отдельно. Для повторного использования изображения с другой компоновкой можно создать вторую сцену с тем же `src`.

### Линейный экран и выбор

```json
{
  "id":"question",
  "scene":"platform",
  "speaker":"guide",
  "position":"auto",
  "text":"어디에 가고 싶어요?",
  "choices":[
    {
      "id":"library",
      "label":"Предложить библиотеку",
      "task":"Скажите, что хотите пойти в библиотеку.",
      "answer":"도서관에 가고 싶어요.",
      "reaction":"좋아요. 같이 가요!",
      "effects":[{"variable":"trust","add":1}],
      "next":"library-scene"
    },
    {
      "id":"cafe",
      "label":"Предложить кафе",
      "task":"Предложите выпить кофе.",
      "answer":"커피 마실까요?",
      "reaction":"네, 좋아요!",
      "next":"cafe-scene"
    }
  ]
}
```

Это пример синтаксиса, не самостоятельная история: все переменные, сцены и целевые экраны нужно определить. Вместо `choices` линейный экран содержит `next`. Концовка содержит `ending: {"title":"…","description":"…"}` без `next` и `choices`. Варианты — от двух до четырёх; `speaker` в выборе переопределяет говорящего в реакции. Поля `answer` видны только преподавателю; автоматической проверки нет.

### Переменные, флаги и условия

Поддерживаются числа, булевы значения, строки и null. Начальное null обозначает ещё не выбранный флаг; после выбора можно записать строковое значение, например first_question = "what". Инициализируйте все переменные в `story.json`: `"variables":{"trust":0,"clue":false}`. Эффекты: `{"variable":"trust","add":1}` или `{"variable":"clue","set":true}`. Улики задаются булевыми переменными, например `foundTicket`. Эффекты применяются один раз при выборе и сохраняются в снимке состояния.

Условие сравнения: `{"variable":"trust","op":"gte","value":2}`. Операторы: `eq`, `ne`, `gt`, `gte`, `lt`, `lte`; для булевых значений только `eq`/`ne`. Комбинации: `{"all":[…]}`, `{"any":[…]}`, `{"not":{…}}` с любой вложенностью. Код из JSON никогда не исполняется.

Любой переход может быть строкой или объектом:

```json
{
  "cases":[
    {"when":{"all":[{"variable":"trust","op":"gte","value":2},{"variable":"clue","op":"eq","value":true}]},"target":"good-ending"}
  ],
  "fallback":"other-ending"
}
```

Проверяется первая подходящая ветка; `fallback` обязателен. Условная реплика: `variants: [{"when":условие,"text":"…"}]` — первая подходящая заменяет обычный `text`. Условный экран: `when` и обязательный `skipTo` — при ложном условии экран пропускается. Защита от циклов пропуска выводит понятную ошибку. `when` у выбора скрывает его; автор должен обеспечить хотя бы один доступный ответ на любом достижимом маршруте.

## Демонстрация

«Последний поезд» — 10 экранов, Юна и Минхо, три последовательных выбора по два варианта. Первый выбор ведёт в разные промежуточные сцены, затем ветви сходятся в бюро находок. Переменные: `trust` и `clue`. Реплики сотрудника меняются в зависимости от найденной улики. Для концовки «Встреча у синей звезды» нужны `trust >= 2` и `clue == true`; иначе — «До завтра, Сеул». Все восемь комбинаций ответов проверяются тестом. Например: «Уточнить» → «Описать» → «Остаться» и «Сразу отдать» → «Поторопить» → «Успеть» приводят к разным концовкам.

## Проверки и ограничения

Валидатор проверяет типы данных, условия, ID, переходы, изображения, незавершённые ветки, недостижимые экраны и отсутствие пути к концовке. Недостижимость проверяется по графу: это не математическое доказательство выполнимости всех комбинаций условий. Такие комбинации проверяйте в режиме преподавателя или маршрутными тестами. В браузере отсутствующее или повреждённое изображение блокирует открытие с указанием пути. Предупреждения графа видны в режиме преподавателя и в команде validate.

Сохранения версионированы, изолированы по ID истории, содержат снимки переменных для каждого посещения и выбранные ответы. Повреждённое или несовместимое сохранение не используется. При изменении ID экранов опубликованной истории желательно также менять ID истории. localStorage не является защищённым хранилищем; режим преподавателя — переключатель интерфейса, а не контроль доступа. Все данные доступны на статическом сайте.

Внешние шрифты Google Fonts необязательны: без сети используются системные шрифты. SVG-иллюстрации входят в проект; внешних изображений нет. Backend, AI, речь, синхронизация и визуальный редактор не включены.

## GitHub Pages

1. Поместите содержимое этой папки в корень GitHub-репозитория (включая `package-lock.json`).
2. В Settings → Pages выберите Source: GitHub Actions.
3. Отправьте изменения в ветку `main`. Готовый workflow проверит истории, выполнит тесты, соберёт и опубликует `dist/`.

В Vite установлен относительный `base: './'`: сайт работает как в корне домена, так и по адресу `/repository/`. Клиентский маршрутизатор не используется. Для другого статического хостинга загрузите содержимое `dist/`.
